# Open-weight medical / MRI foundation models as encoders for RSNA knee multi-label classification (research as of 2026-10-04)

Scope note: focus is 2024-2026 releases that can be downloaded and run offline on 2x T4 (fp16 only). "Evidence" means published numbers; where I could only find a model card or abstract I say so. Items labelled Inference are my reasoning, not sourced facts. Nothing was downloaded (only an HTTP HEAD request to check that one large weight file is reachable).

---

## Key Question 1: Which open-weight 2D/3D medical or MRI foundation models exist, and what are their data provenance, size, input, license, hosting?

### Takeaway
There is no widely validated, open, MRI-pathology-trained 2D encoder that clearly beats a good general model. The realistic pool is: (a) general SSL models (DINOv3 / DINOv2) that are open, timm-native and cheap enough for T4; (b) one knee-specific model (OrthoFoundation-L, DINOv3-L continued-pretrained on knee X-ray+MRI incl. OAI and fastMRI; weights on GitHub, MIT) that is heavy and unreplicated; (c) a few medical encoders (MRI-CORE, MedImageInsight, MedSigLIP, BiomedCLIP) with weak or no knee-MRI-pathology evidence; (d) 3D/CT/chest/brain models that do not fit this task.

### Cited Findings

**General SSL models (not medical, but the leading candidates)**
- DINOv3 released 13 Aug 2025 (arXiv 2508.10104). Open family: ViT-S/16 (21M), S+/16 (29M), B/16 (86M), L/16 (300M), H+/16 (840M), 7B; ConvNeXt T/S/B/L (29M/50M/89M/198M); LVD-1689M web data (plus two satellite ViT-L/7B variants). Supported in HF Transformers >=4.56.0 and timm >=1.0.20. License is the "DINOv3 License". — [DINOv3 GitHub](https://github.com/facebookresearch/dinov3), [DINOv3 paper](https://arxiv.org/pdf/2508.10104)
- DINOv3 License: royalty-free, commercial use permitted; if you distribute materials/derivatives you must include the agreement and prominently show "Built with DINOv3", and acknowledge use in published research; prohibits military/nuclear/espionage/weapons/ITAR uses; says nothing explicit about competitions. It is NOT an OSI license (relevant if a prize requires open-sourcing; check competition rules). — [DINOv3 License](https://ai.meta.com/resources/models-and-libraries/dinov3-license/)
- HF `facebook/dinov3-*` repos are gated (contact-info form). The `timm/` copies are not gated per the model card. — [facebook/dinov3-vits16](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m), [timm/vit_base_patch16_dinov3](https://huggingface.co/timm/vit_base_patch16_dinov3.lvd1689m)
- timm DINOv3 specs (default 256x256 input): ViT-S/16 21.6M params, 6.3 GMACs; ViT-B/16 85.6M, 23.6 GMACs; ViT-L/16 303.1M, 82.4 GMACs; ConvNeXt-T 27.8M, 4.5 GMACs @224; ConvNeXt-S 49.5M, 8.7 GMACs @224. Model IDs: `vit_small_patch16_dinov3.lvd1689m`, `vit_base_patch16_dinov3.lvd1689m`, `vit_large_patch16_dinov3.lvd1689m`, `convnext_tiny.dinov3_lvd1689m`, `convnext_small.dinov3_lvd1689m`. — [ViT-S](https://huggingface.co/timm/vit_small_patch16_dinov3.lvd1689m), [ViT-B](https://huggingface.co/timm/vit_base_patch16_dinov3.lvd1689m), [ViT-L](https://huggingface.co/timm/vit_large_patch16_dinov3.lvd1689m), [CNX-T](https://huggingface.co/timm/convnext_tiny.dinov3_lvd1689m), [CNX-S](https://huggingface.co/timm/convnext_small.dinov3_lvd1689m)
- DINOv3 ViTs use RoPE and 4 register tokens, patch 16 (so token grid = H/16 x W/16; 224/336 work, min 128 per a Kaggle mirror note). timm disables zero-valued qkv biases and creates float32 RoPE periods at init for devices without bf16 (relevant to T4). — [HF card](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m), [Kaggle mirror](https://www.kaggle.com/models/gchauhan/dinov3), [timm card](https://huggingface.co/timm/vit_base_patch16_dinov3.lvd1689m)
- Offline hosting on Kaggle already exists: `gchauhan/dinov3` (ViT-B/16 lvd1689m timm safetensors, uploaded 2026-09-13, description says it is for offline RSNA knee kernels; requires timm>=1.0.20, ImageNet mean/std, 5 prefix tokens = CLS + 4 registers); `keras/dinov3` (Keras ports S/S+/B/L/H+/7B). — [gchauhan/dinov3](https://www.kaggle.com/models/gchauhan/dinov3), [keras/dinov3](https://www.kaggle.com/models/keras/dinov3)
- DINOv2 ViT-S/14 (21M) and ViT-B/14 (86M) are the models used in the knee-MRI paper below (MST). — [MST](https://arxiv.org/abs/2411.15802)

**Knee-specific**
- OrthoFoundation (arXiv 2601.18250, Jan 2026, preprint v1, Beihang Univ + Peking Univ Third Hospital): DINOv3-Large backbone, continued self-supervised (DINO student-teacher, multi-crop) pretraining on 1,251,655 knee images = 357,670 radiographs + 893,985 MRI slices. Sources: OAI (100k X-rays + 200k MRI slices), fastMRI knee (300k MRI slices), internal PUTH-Group (200k X-rays + 200k MRI slices; private/restricted). — [arXiv](https://arxiv.org/abs/2601.18250v1), [alphaXiv overview](https://www.alphaxiv.org/overview/2601.18250), paper PDF text (fetched locally)
- OrthoFoundation weights: GitHub repo `ytrsk/OrthoFoundation`, MIT license, file `OrthoFoudation-L.pth` stored via Git LFS (pointer says 1,213,056,638 bytes ~1.13 GiB, i.e. ViT-L fp32). The README says weights are "released in this repository"; the repo includes training scripts (4xA100). An HTTP HEAD on `media.githubusercontent.com/media/ytrsk/OrthoFoundation/main/OrthoFoudation-L.pth` returned 200 with Content-Length 1213056638 on 2026-10-04 (file not downloaded). — [GitHub](https://github.com/ytrsk/OrthoFoundation), [LFS pointer](https://raw.githubusercontent.com/ytrsk/OrthoFoundation/main/OrthoFoudation-L.pth)
- OrthoFoundation internal inconsistency: methods text says the ViT is "initialized with DINOv2 weights" while the abstract/README say DINOv3-Large. Input size and fine-tuning LR/epochs are not stated in the paper or README. Fine-tuning treated MRI slices independently (the authors list this as a limitation). — paper PDF text, [GitHub README](https://raw.githubusercontent.com/ytrsk/OrthoFoundation/main/README.md)
- Other knee-specific SSL work found: an OAI-DINO ISMRM 2025 abstract and ACL-LKNet (masked-slice-modeling, HF `shareefch1413/ACL-LKNet`), KneeXNet, SB-SSL (slice-based SSL transformer, 2022). I did not verify weights, pretraining data (MRNet likely) or benchmarks for any of these. — [ISMRM 2025 abstract](https://archive.ismrm.org/2025/4014.html), [ACL-LKNet](https://huggingface.co/shareefch1413/ACL-LKNet), [SB-SSL](https://arxiv.org/pdf/2208.13923)

**MRI-specific / multi-region medical encoders**
- MRI-CORE (Duke, arXiv 2506.12186, June 2025): 2D ViT-B (SAM-initialized image encoder, then DINOv2-style SSL, ~4 epochs / ~50k iterations), input 1024x1024, pretrained on Duke-110K = 6.9M slices from 116,806 volumes, 18 body locations, 9+ sequences, single institution (2016-2020), no brain. Code+weights at `mazurowski-lab/mri_foundation`; weights are a manual Google Drive download (not HF); GitHub says Apache-2.0, paper says CC BY 4.0. Knee appears only as an evaluation set (KNEEMRI: 4,554 slices / 1,217 volumes, normal vs abnormal) - no number reported for it. — [arXiv HTML](https://arxiv.org/html/2506.12186v2), [GitHub](https://github.com/mazurowski-lab/mri_foundation)
- MedImageInsight (Microsoft, arXiv 2410.06542, Oct 2024): two-tower UniCL model, DaViT image encoder 360M (language encoder 252M), 480x480 input, trained on X-ray/CT/MRI/derm/OCT/US/histopath etc. Data table lists MRI sources such as UPENN-GBM and TCGA MRI/CT plus a Bing-crawled "exam parameter" set that includes knee MRI exam-type labels; no MRNet / OAI / fastMRI mention appears anywhere in the paper text I extracted. Open weights on HF mirror `lion-ai/MedImageInsights` (reported MIT) and Azure catalog. — [paper](https://arxiv.org/abs/2410.06542), [HF mirror](https://huggingface.co/lion-ai/MedImageInsights), [DEV post](https://dev.to/aleksanderobuchowski/medimageinsight-open-source-medical-image-embedding-model-now-on-huggingface-3b63)
- MedSigLIP (Google, model created 9 Jul 2025): 400M vision encoder + 400M text encoder, 448x448 input; trained on CXR, derm, ophtho, histopath, and slices of CT and MRI volumes; no knee/MSK-specific results reported (a Mendeley digital knee X-ray set is in training data). Weights `google/medsiglip-448` on HF under Health AI Developer Foundations terms; Kaggle `keras/medsiglip` preset `medsiglip_900m_448` (3.5 GB). — [model card](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card), [Kaggle](https://www.kaggle.com/models/keras/medsiglip)
- BiomedCLIP (Microsoft): ViT-B/16 @224 vision encoder (ImageNet-initialized), pretrained on PMC-15M figure-caption pairs, MIT license, on HF; Kaggle mirror `mrquadian/biomedclip` exists. — [paper](https://arxiv.org/pdf/2303.00915), [Kaggle](https://www.kaggle.com/models/mrquadian/biomedclip)
- Triad (Emory, arXiv 2502.14064, Feb 2025; Medical Image Analysis 2026): 3D MAE/SimMIM-pretrained Swin-B (72.8M) and nnUNet encoders on 131,170 brain/breast/prostate MRI volumes (36 public sets, incl. fastMRI brain/breast/prostate), input 256x256x128; knee NOT included; no MSK task. Weights on Google Drive via `wangshansong1/Triad` (repo MIT; paper CC BY 4.0). — [arXiv HTML](https://arxiv.org/html/2502.14064v1), [GitHub](https://github.com/wangshansong1/Triad)
- Decipher-MR (GE HealthCare, arXiv 2509.21249, Sep 2025): 3D ViT-B (86M) on 203,233 MRI series / 22,594 studies, knee is one of the regions but no MSK benchmark; the paper states no code/weights release. Not usable. — [arXiv HTML](https://arxiv.org/html/2509.21249v2)
- RadImageNet (Mei et al., Radiology: AI 2022): CNNs (ResNet50, DenseNet121, InceptionV3, InceptionResNetV2) pretrained on 1.35M CT/MRI/US images (11 anatomical regions, 165 labels, includes musculoskeletal MRI); repo MIT; weights via Google Drive; Swin weights only "planned". No newer RadImageNet successor found. — [GitHub](https://github.com/BMEII-AI/RadImageNet), [paper](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9530758/)

**Models that do not fit (modality/dimension mismatch)**
- RAD-DINO (Microsoft): ViT-B/14 DINOv2 trained on ~840k chest X-rays only; MSRLA license (an MIT variant is also mentioned). Chest radiographs, not MRI. — [paper](https://arxiv.org/pdf/2401.10815), [HF](https://huggingface.co/microsoft/rad-dino)
- Merlin (Stanford, CT vision-language), CT-FM, VoCo (CT 3D): CT-only; BrainIAC (brain MRI): code+weights public but non-commercial research use only (per a secondary summary). — [Merlin](https://arxiv.org/abs/2406.06512), [BrainIAC GitHub](https://github.com/AIM-KannLab/BrainIAC), [summary of BrainIAC licence](https://themenonlab.blog/blog/brainiac-self-supervised-brain-mri-foundation-model)
- MedicalNet (3D ResNet, Tencent, 2019), VoCo (3D Swin-UNETR) were benchmarked in AnyMC3D (see Q2) and lost clearly to 2D FMs. — [AnyMC3D](https://arxiv.org/abs/2512.12887)
- SAM / MedSAM / MedSAM2 / SAM-Med3D encoders are segmentation-trained; in the MedMNIST FM benchmark SAM (segmentation-trained) was consistently worse for classification than SAM-C (classification-trained) especially under linear probing. I did not research MedSAM2 / SAM-Med3D in depth. — [MedMNIST FM benchmark](https://arxiv.org/pdf/2501.14685)

**Provenance flags for competition rules**
- OAI and fastMRI are public knee-MRI datasets (OAI is also the source of many OA labels) and OrthoFoundation also used private PUTH knee MRI. None of the candidates states it used MRNet or KneeCoT for pretraining. MRNet appears only as a downstream evaluation set in the MST paper. — [OrthoFoundation](https://arxiv.org/abs/2601.18250v1), [MST](https://arxiv.org/abs/2411.15802)
- MRI-CORE pretraining is Duke-only (private, single institution); MedImageInsight, MedSigLIP and BiomedCLIP use mixed/web/private medical data. — [MRI-CORE](https://arxiv.org/html/2506.12186v2), [MedSigLIP card](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card)

### Inferences
- OrthoFoundation-L is the only open model whose pretraining actually contains knee MRI, which makes it the only candidate with a plausible domain-prior advantage, but it also carries the largest rules risk (OAI + fastMRI + private clinical knee MRI baked into the weights). Whether "publicly released pretrained weights are generally OK" covers weights trained on public knee datasets such as OAI/fastMRI should be confirmed against the competition's external-data rule before investing GPU hours.
- ViT-L (303M, 82 GMACs @256) is expensive for T4 training; a ViT-L-only knee model is hard to use except as frozen features or with LoRA.
- Medical models trained mainly on chest X-ray/derm/path/CT (RAD-DINO, MedSigLIP, BiomedCLIP, Merlin) have little reason to encode MSK MRI soft-tissue contrast better than a good natural-image SSL model.

### Gaps
- Could not verify OrthoFoundation weights actually load / their input resolution / expected preprocessing; did not download. License of any commercial/competition constraint on weights trained from OAI data not checked (OAI has its own data use agreement).
- Did not find licenses/weights for OAI-DINO (ISMRM abstract), ACL-LKNet's training data, KneeXNet; did not verify UniMed-CLIP, MedMAE/VIS-MAE, MedSAM2, SAM-Med3D (only surfaced in search, not read).
- Exact MedImageInsight HF license is from a third-party mirror/blog (MIT claimed), not from Microsoft's official card; official Azure terms not checked.
- No independent knee-MRI evaluation exists (to my search) for MRI-CORE, MedImageInsight, MedSigLIP, or Triad.

## Key Question 2: What benchmark evidence shows these beat ImageNet initialisation on MRI / MSK classification?

### Takeaway
Evidence is thin and mostly indirect. The best direct knee-MRI datapoints show DINOv2-S fine-tuning ahead of an ImageNet ResNet50 by ~0.07 AUC on MRNet meniscus in one small study (not significant), while the literature on RadImageNet (the "medical pretraining" baseline) is contradictory and agrees with the user's own finding that it does not beat ImageNet. A December 2025 multi-task benchmark with shoulder MRI shows a properly adapted general DINOv3 matches the best medical encoder, and that frozen medical encoders are not enough by themselves.

### Cited Findings
- MST (Medical Slice Transformer, Nov 2024), MRNet knee meniscus tear (1,199 patients, 224x224 slices): DINOv2-S encoder + slice-transformer AUC 0.85 +/- 0.04 vs 3D ResNet50 0.69 +/- 0.05 (P=0.001). Variants (AUC): DINOv2-B 0.83, DINOv2+registers 0.82, DINOv2 frozen 0.79 (P=0.14), same MST with an ImageNet ResNet50 slice encoder 0.78 (P=0.07). On breast MRI and chest CT freezing DINOv2 collapsed to 0.62 and 0.66 AUC (fine-tuning is necessary). Larger DINOv2-B did not help. — [MST arXiv](https://arxiv.org/abs/2411.15802), paper PDF text (Tables 2-3, fetched locally)
- AnyMC3D (Dec 2025, arXiv 2512.12887): 12-task 3D benchmark with shoulder MRI tasks (biceps tear, bursa fluid, labrum tear; no knee). Frozen ViT-L 2D FMs + LoRA(rank 8, ~1.2M trainable) + query-based attention slice pooling: avg AUC DINOv3 0.894 vs MedImageInsight 0.894 (rank 2.0 vs 1.7) vs MedGemma-SigLIP 0.866; frozen medical FMs with simple fusion were much worse (MII 0.785, MedGemma 0.690). Shoulder MRI AUCs (biceps / bursa / labrum): AnyMC3D-DINOv3 0.856 / 0.892 / 0.793; AnyMC3D-MII 0.865 / 0.889 / 0.795; MST (full DINOv2-S fine-tune) 0.852 / 0.859 / 0.778; RSNA-Kaggle-style 2.5D EfficientNet+BiLSTM 0.782 / 0.882 / 0.584; 3D ResNet 0.699 / 0.826 / 0.686; MedicalNet 3D 0.679 / 0.801 / 0.676; VoCo 3D 0.746 / 0.852 / 0.702. — [AnyMC3D](https://arxiv.org/abs/2512.12887), paper PDF text (Table 2, fetched locally)
- AnyMC3D ablations: query-based attention pooling over slices beat average/median/max pooling and Transformer/LSTM fusion on PDAC (0.962 vs 0.958/0.944/0.946/0.950/0.903); replacing naive pooling with attention fusion gave +0.11 AUC with identical backbones; DINOv3 vs DINOv2 "negligible differences, neither consistently outperforms" for image-level tasks; stacking 3 consecutive slices (2.5D) performed comparably to replicating a single slice 3x; ViT-S/B/L DINOv3 AUCs on 3 CT tasks 0.980/0.975/0.988 (kidney), 0.933/0.943/0.962 (PDAC), 0.881/0.902/0.903 (spiculation), all within ~0.01-0.03. — [AnyMC3D](https://arxiv.org/abs/2512.12887), paper PDF text (Sec. F, Tables 6-8)
- OrthoFoundation (Jan 2026): reports "ranked first" on 10 binary knee-MRI injury tasks (ACL, PCL, medial/lateral meniscus, MCL, LCL, patellar dislocation, medial retinaculum, bone bruise, cartilage) on a private PUTH dataset (200k MRI images, 18,726 patients); PCL AUC 84.3, 4 points above the second-best (In-ViT, presumably an ImageNet-pretrained ViT; not defined in the text I extracted); ACL AUC 97.7 with 50% labels and 98.49 per the README; on non-knee MSK tasks (hip labral tear, rotator cuff, ATFL, CFL) AUC 83.7/86.1/86.9/70.6 and 3-4 points average gain over DINOv2, DINOv3, In-ViT baselines. Per-task tables for meniscus etc. are in figures I could not extract; baseline fine-tuning recipes are not given; 5-fold CV with t-tests. — paper PDF text (fetched locally), [GitHub](https://github.com/ytrsk/OrthoFoundation)
- RadImageNet vs ImageNet: original RadImageNet paper claimed an average 4.5% AUC gain on small radiologic datasets including meniscal tear (MRI). — [RadImageNet paper](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9530758/)
- Counter-evidence: on MRNet ACL (1021 exams) ImageNet-pretrained ResNet50 beat RadImageNet statistically (p=0.017); best test AUC 0.9969 with ImageNet ResNet50 + convolutional classifier + partial unfreezing (top 5 layer groups), SGD+momentum, cosine annealing. Another study found overall ImageNet > RadImageNet, and another found the knee set equal under both. — [ACL study 2508.17567](https://arxiv.org/html/2508.17567v2), [Revisiting hidden representations](https://arxiv.org/pdf/2302.08272)
- In-domain SSL does not always beat ImageNet: on knee radiograph OA grading (OAI/MOST), ImageNet 0.646 balanced accuracy vs MoCo 0.636 at 10% labels; multimodal image-text SSL (ConVIRT) helped prognosis (AUROC 0.701 vs 0.599). Radiographs only, not MRI. — [knee OA SSL study](https://arxiv.org/html/2603.24903v1)
- DINOv2 radiology benchmark (Dec 2023, over 100 experiments): linear-probe DINOv2 on par or slightly better than supervised baselines in X-ray/CT/MRI classification; weak kNN performance; only two MRI sets (brain tumor classification, MSD heart segmentation), no knee/MSK. — [DINOv2 radiology benchmark](https://arxiv.org/html/2312.02366v1)
- Imperial benchmark of DINOv3 (Sep 2025, frozen + linear probe/light decoder): CT-RATE DINOv3-B AUC 0.798 vs CT-CLIP 0.731; NIH-14 DINOv3-L 0.7865 vs BiomedCLIP 0.7771; fails badly on EM, PET, and WSI vs pathology FMs; no MRI classification benchmark; 2D classification peaked at 512 px and larger models underperformed smaller ones on some 2D tasks ("DINOv3 does not consistently follow the expected scaling laws in the medical domain"). — [Does DINOv3 Set a New Medical Vision Standard?](https://arxiv.org/html/2509.06467v2)
- MSK segmentation (not classification): SAM2 outperformed SAM and MedSAM across 11 MSK MRI datasets, e.g. shoulder CUBE Dice 0.68 vs 0.55 (SAM) vs 0.32 (MedSAM). MRI-CORE reports gains over SAM/MedSAM on 13 segmentation tasks, strongest on MSK bone/muscle. — [MSK FM segmentation study](https://arxiv.org/html/2501.13376v3), [MRI-CORE](https://arxiv.org/html/2506.12186v2)
- Triad: Swin-B-Triad +3.97% over Swin-B-Scratch on 5 3D classification sets (brain/breast/CT); MSK tasks none. — [Triad](https://arxiv.org/html/2502.14064v1)
- MedMNIST FM benchmark (Jan 2025, 12 models): end-to-end fine-tuning beat linear probing everywhere (one AUC exception); ViT-based models (DINO/DINOv2/ViT-B/16) usually best; BiomedCLIP/MedSAM numbers quoted from another paper were lower than the tuned natural-image ViTs on the sets shown (different protocol). Low-resolution 2D MedMNIST, not MRI-slice at diagnostic resolution. — [MedMNIST benchmark](https://arxiv.org/pdf/2501.14685)

### Inferences
- The only published knee-MRI head-to-head of SSL-DINO vs ImageNet-CNN (MST, MRNet meniscus) shows +0.07 AUC but P=0.07 and SD 0.04, so it is suggestive, not proof. The user's own observation (RadImageNet-R50 no gain over ImageNet) agrees with the 2025 literature, so "medical-pretrained CNN" is not a reliable lever here.
- AnyMC3D's results mirror the user's pipeline (2.5D slices + attention pooling over slices), and the paper's own RSNA-Kaggle-style EfficientNet baseline was competitive on 1 of 3 shoulder MRI tasks (bursa 0.882 vs 0.892), behind on biceps (0.782 vs 0.856) and collapsed on labrum (0.584 vs 0.793). This suggests ViT/DINO encoders may help most when labels are rare/hard and EfficientNet may be on par when signal is easy; per-finding gains (rare findings such as fracture/contusion/synovitis) are where to look.
- OrthoFoundation's headline claims come from a private dataset with unstated baseline recipes; treat as upper-bound hype until reproduced on RSNA data.

### Gaps
- No published benchmark of DINOv3 / MedSigLIP / MedImageInsight / MRI-CORE / OrthoFoundation on public multi-label knee MRI (e.g. MRNet ACL+meniscus or OAI-MRI findings) by independent authors.
- No Kaggle write-up found (RSNA 2024 lumbar spine winners' solutions are localize-then-classify with 2.5D stacks; I did not find evidence that winners used DINO/medical FMs). The in-competition forum was not searched by me (covered by other researchers).
- AnyMC3D has no knee set; extrapolation to knee is an inference.

## Key Question 3: Is DINOv3 usable for medical fine-tuning, and what LR / unfreezing recipes work for ViTs on small medical datasets?

### Takeaway
Yes: DINOv3 weights are openly downloadable (license permits commercial use with attribution; timm copies are ungated) and a small ViT (S/B) can be fine-tuned on a T4. Published recipes for small medical sets point to backbone LR around 1e-5 (down to 1e-6 for long schedules), a much larger head LR (1e-3), AdamW with weight decay 1e-2 to 1e-5, layer-wise LR decay 0.65-0.75, many epochs, and LoRA (r=8) as a stable alternative. The user's 3e-5 x 6 epochs underfit is consistent with schedule/head-LR problems rather than a wrong model family, but this is an inference.

### Cited Findings
- DINOv3 authors recommend frozen features and say fine-tuning should be a last resort. — [DINOv3 HF card via search summary](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m)
- Imperial DINOv3 medical benchmark protocol: frozen backbone + linear probe, BCE, LR 0.005, 50 epochs, batch 1024; for WSI a learnable projection + attention MIL (ABMIL) head over frozen DINOv3 features; segmentation decoders AdamW LR 1e-4 cosine. Explicitly did not study full fine-tuning or PEFT. — [DINOv3 medical benchmark](https://arxiv.org/html/2509.06467v2)
- MedMNIST FM benchmark: for ViT-based models the best end-to-end encoder LR was 1e-5 (searched {1e-4, 1e-5, 1e-6}); for CNNs 1e-4 (searched {1e-3, 1e-4, 1e-5}); a different pipeline (AdamW LR 1e-4, single-cycle cosine) gave notably worse ViT fine-tuning (e.g. BreastMNIST ViT-B/16 AUC 86.18 vs 94.09 with the tuned encoder-specific LR). — [MedMNIST benchmark](https://arxiv.org/pdf/2501.14685)
- MST (knee/breast/chest, DINOv2-S, batch size 2 studies, fp16): AdamW, weight decay 1e-2, LR 1e-6 for the DINOv2-based model (1e-5 for ResNet50 slice encoder, 1e-4 for 3D ResNet), weighted sampling for class imbalance, training until validation AUC did not improve for 50 epochs, TorchIO flip/noise/rotation/signal-inversion augmentation. — [MST paper text](https://arxiv.org/abs/2411.15802), fetched locally
- AnyMC3D adaptation recipe: frozen ViT-L + LoRA (r=8, alpha=16) on patch embedding and all attention projections; LoRA LR 1e-4 (wd 1e-5), task query + linear head LR 1e-3 (wd 1e-4); focal loss (gamma 2, alpha 0.25); batch size 2; up to 100 epochs, best-val checkpoint; ImageNet mean/std on 3-channel replicated slices; ~0.23M / 0.46M / 1.20M trainable params for ViT-S/B/L. Recommends starting with ViT-S and scaling up. — [AnyMC3D](https://arxiv.org/abs/2512.12887)
- Natural-image FMs fine-tuned on mammography/skin/retina/CheXpert (2505.19779): AdamW, LR searched 1e-3..1e-5, 224 px; unfrozen backbones with a linear head gave the best results overall; with frozen backbones multi-layer attention heads beat linear heads; AIMv2 was best, then DINOv2 and SAM2. DINOv3 not included, no MRI. — [fine-tuning natural FMs](https://arxiv.org/html/2505.19779v1)
- Layer-wise LR decay: widely used LLRD values are about 0.65-0.75 (MAE recipe uses 0.75; BEiT 0.65 or 0.75 depending on model size). The source is a search summary of the MAE paper, not a medical study; no medical paper I read applied LLRD with DINOv3. — [MAE paper](https://arxiv.org/pdf/2111.06377)
- Resolution: DINOv3 benchmark found 2D classification peaked at 512 px on chest X-ray (NIH-14) before declining; MST used 224x224 crops; DINOv3 ViTs use RoPE so non-square/other multiples of 16 work without positional-embedding interpolation. — [DINOv3 medical benchmark](https://arxiv.org/html/2509.06467v2), [Kaggle mirror notes](https://www.kaggle.com/models/gchauhan/dinov3)
- DINOv3 vs DINOv2 for image-level classification: "negligible differences" (AnyMC3D). DINOv3's main change (Gram anchoring) targets dense features. — [AnyMC3D](https://arxiv.org/abs/2512.12887)

### Inferences
- A concrete recipe worth one 4-6 GPU-hour trial on a single fold: DINOv3 ViT-S/16 or B/16 via timm, 2.5D 3-channel input at 224-288 (multiples of 16: 224/256/288), backbone AdamW LR ~1e-5 with LLRD ~0.75 (higher for later blocks), head/attention-MIL LR 1e-3 to 3e-4, wd 0.01-0.05, 5% warmup then cosine, >= 15-30 epochs of the slice-sampled data, and a "head-only warm-up" for the first epoch. Alternative with lower variance: LoRA r=8 on all attention projections (LR 1e-4) with the existing attention-MIL head at LR 1e-3.
- Reasons the earlier DINOv2-S run underfit (inferred, not proven): backbone LR 3e-5 was applied together with a short 6-epoch schedule while published knee/ViT recipes run until plateau (MST patience 50 epochs at 1e-6) and give heads 10-1000x higher LR; also frozen/low-LR ViTs are known to need many epochs. An ablation order that isolates the cause: (1) LoRA + head 1e-3, (2) full FT at 1e-5 + LLRD, (3) more epochs.
- DINOv3 ConvNeXt (T 4.5 / S 8.7 GMACs @224) is an untested "drop-in" for the existing CNN branch (same 2.5D pipeline, CNN-style LRs like 1e-4); no medical evidence found for it, so it is speculative.

### Gaps
- No paper found applying DINOv3 + LLRD to MRI; LLRD numbers come from natural-image recipes.
- fp16 (no bf16) stability of DINOv3 ViT fine-tuning on T4 is unverified; DINOv3 was trained in bf16. Watch for inf/NaN in attention/LayerScale; keep GradScaler and optionally keep RoPE/LayerNorm in fp32.
- Competition license issue: whether DINOv3 License (non-OSI, "Built with DINOv3" attribution) is acceptable for a prize-eligible open-source requirement was not checked.

## Key Question 4: Practical T4 memory/speed at 224-384 px, fp16, timm availability

### Takeaway
ViT-S and ViT-B (DINOv3, timm >= 1.0.20, fp16 autocast) are practical for training and inference on 2x T4; ViT-L-class models (OrthoFoundation-L, MedImageInsight, MedSigLIP) are only practical as frozen/LoRA feature extractors. Compute is dominated by the 60 GPU-hour training budget, not by inference.

### Cited Findings
- T4 has 65 TFLOPS peak half-precision (vs V100 112); no bf16. — [search summary of NVIDIA specs](https://apxml.com/hardware/nvidia-t4-16gb)
- Throughput reference on one 16 GB V100 with AMP at 224px: DeiT-S 940 img/s, DeiT-B 292 img/s. — [DeiT paper](https://arxiv.org/pdf/2012.12877)
- timm GMACs: DINOv3 ViT-S 6.3 / B 23.6 / L 82.4 at 256 px (patch 16, 256 tokens + 5 prefix tokens). Activations (M): B 34.1, L 90.6 at 256 px. ConvNeXt-T 4.5 and ConvNeXt-S 8.7 GMACs at 224. — [timm ViT-S](https://huggingface.co/timm/vit_small_patch16_dinov3.lvd1689m), [ViT-B](https://huggingface.co/timm/vit_base_patch16_dinov3.lvd1689m), [ViT-L](https://huggingface.co/timm/vit_large_patch16_dinov3.lvd1689m), [CNX-T](https://huggingface.co/timm/convnext_tiny.dinov3_lvd1689m), [CNX-S](https://huggingface.co/timm/convnext_small.dinov3_lvd1689m)
- Other model sizes: MedImageInsight image tower 360M @480; MedSigLIP vision tower 400M @448; MRI-CORE SAM-ViT-B @1024 (default); DINOv3 ViT-H+ 840M. — [MII](https://arxiv.org/abs/2410.06542), [MedSigLIP](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card), [MRI-CORE](https://github.com/mazurowski-lab/mri_foundation)
- timm DINOv3 support: timm>=1.0.20 and `timm.create_model("hf-hub:timm/vit_base_patch16_dinov3.lvd1689m", pretrained=True)`; offline: use `pretrained_cfg_overlay=dict(file=...)` with the Kaggle mirror safetensors. — [timm card](https://huggingface.co/timm/vit_base_patch16_dinov3.lvd1689m), [Kaggle gchauhan/dinov3](https://www.kaggle.com/models/gchauhan/dinov3)

### Inferences (my estimates, label as such; benchmark before relying)
- Token counts at patch 16: 224 -> 196, 256 -> 256, 288 -> 324, 336 -> 441, 384 -> 576 tokens; ViT cost grows roughly linear-to-quadratic in tokens, i.e. 384 px costs ~2.3x of 256 px for ViT-B (roughly 55 GMACs; ~190+ for ViT-L).
- Order-of-magnitude on a single T4 fp16: ViT-B @256 inference ~80-120 img/s, ViT-S @256 ~250-350 img/s, ViT-L @256 ~25-40 img/s (derived from DeiT V100 numbers scaled by ~2-3x slower and the GMAC ratios). Training fwd+bwd is ~3x slower, so ViT-B @256 trains at perhaps 25-40 img/s per T4. A rough total for 60 GPU-hours of ViT-B training is only ~5-8M slice passes, i.e. a handful of full epochs over ~1M slices (4,400 studies x ~250 slices) - so slice subsampling (centre slices per series) or LoRA/frozen-feature caching is required.
- Test-time: ~1,300 studies x ~250 slices = ~325k slice forwards; ViT-B @256 on 2xT4 ~ 30-45 min; ViT-L @256 ~2-2.5 h; both fit inside 9 h even with a few ensemble members, but only a 1-2 model ensemble of L fits alongside the existing EfficientNet/ResNet branches.
- Frozen-feature caching of ViT-B CLS embeddings (768-d, fp16) for all slices is ~1.5 KB/slice, ~1.7 GB total, so the attention-MIL head could be trained for many epochs in minutes; but frozen DINO features lost 0.06 AUC on knee meniscus and collapsed on other MRI in MST, so frozen should only be a cheap screening test of "does this encoder carry knee signal" (linear/MIL probe on 5k slices), not the final model.
- EfficientNet-B0 is ~0.4 GMACs @224; ViT-S is ~16x and ViT-B ~60x FLOPs per image, though depthwise-conv EfficientNet is memory-bound so wall-clock ratios are smaller.

### Gaps
- No published T4 throughput for DINOv3 ViTs or any of the medical encoders was found; all numbers above are estimates.
- Memory/OOM thresholds (batch size per T4 at 288/384 with gradient checkpointing) not measured.
- Unverified: FlashAttention-2 is believed to need Ampere+ (not T4), so T4 would rely on PyTorch SDPA's memory-efficient kernel; not benchmarked here.

### Inferences
- Plan A (cheap, evidence-backed): replace or add one DINOv3 ViT-S/16 (or B/16) branch to the ensemble using the recipe in Q3, trained on a single fold first and compared per-finding on OOF AUC; DINOv3 ViT-S/B add ensemble diversity (ViT vs CNN) even if solo AUC is only equal to EfficientNet.
- Plan B (screening, ~1 GPU-h each): extract frozen CLS (or mean-patch) features from OrthoFoundation-L, DINOv3-B, MRI-CORE on a subsample of studies and fit the existing attention-MIL head or logistic regression; if OrthoFoundation-L frozen is not clearly better than DINOv3-B frozen on rare findings (fracture, contusion, synovitis, Baker's cyst), drop it. Only then consider LoRA on the survivors.
- Skip MedSigLIP/MedImageInsight for fine-tuning (400M towers at 448/480 px do not fit the 60 GPU-hour T4 budget); they only make sense as frozen extractors and AnyMC3D shows their frozen features are the weak configuration.
- Verify (a) competition external-data / pretrained-weights rules regarding OAI/fastMRI-derived weights and (b) acceptable license (DINOv3 non-OSI) before choosing a final ensemble member.

### Gaps
- No evidence for any candidate on a RSNA-style 12-finding knee multi-label task; every ranking is extrapolated from MRNet-meniscus (single small study), shoulder MRI (AnyMC3D) and CT tasks.
- OrthoFoundation preprint (v1, not peer reviewed in anything I found) has an internal DINOv2/DINOv3 contradiction and private data; treat claims cautiously.
- Did not examine UniMed-CLIP, MedMAE/VIS-MAE, MedSAM2, SAM-Med3D, KneeXNet, ACL-LKNet in depth.
